# Как мы работаем с репозиторием

## Главное правило

В ветку `main` никто не пишет напрямую. Каждая задача из YouGile — это отдельная ветка и pull request (PR), который проверяет другой участник. В `main` попадает только то, что запускается и прошло ревью.

## Один раз

1. Пришлите руководителю свой логин GitHub — он добавит вас в репозиторий.
2. Примите приглашение: оно придёт на почту или в https://github.com/notifications.
3. Установите [GitHub Desktop](https://desktop.github.com) — в нём всё делается кнопками. Можно работать и через VS Code или командную строку.
4. File → Clone repository → `SamNitelno/TPU-event-calendar`.
5. Создайте виртуальное окружение и установите зависимости (см. README).

## Каждая задача

1. **Взять карточку** в YouGile и перевести её в «В работе».
2. **Обновить main.** В GitHub Desktop: Current branch → `main` → Fetch origin → Pull origin.
3. **Создать ветку** от `main`: Current branch → New branch. Имя — номер карточки и пара слов латиницей.
4. **Работать в своей папке** (таблица в README). Если нужно поменять чужую часть — сначала договориться с её владельцем.
5. **Делать коммиты** небольшими шагами. Сообщение — что сделано, по-русски: «Добавлена таблица vk_posts».
6. **Push origin**, затем **Create pull request**. Название PR — как у карточки. Заполнить шаблон и справа в Reviewers выбрать ревьюера из таблицы в README.
7. **Карточку** перевести в «На проверке», в чат карточки — ссылку на PR.
8. **Ревьюер в течение суток** забирает ветку к себе, запускает её и читает изменения. Затем Approve или Request changes с конкретными замечаниями.
9. **После Approve** автор нажимает Merge pull request и удаляет ветку. Ревьюер переводит карточку в «Готово».

## Что нельзя класть в репозиторий

- `.env`, ключи и токены VK. Они лежат только в `.env` на своём компьютере, образец — `.env.example`.
- Файлы базы данных (`*.db`), папки `venv/`, `__pycache__/`.
- Личные данные людей.

Если ключ случайно попал в GitHub, сразу сообщите руководителю и выпустите новый ключ в настройках приложения VK. Удаление файла не помогает: ключ остаётся в истории.

## Если меняется общий формат

Поля события описаны в [docs/event_format.md](docs/event_format.md). Если задача меняет поле (имя, тип, обязательность), обновите этот файл в том же PR и позовите в ревью всех, кого это касается.

## Конфликты

Если GitHub пишет «This branch has conflicts», не нажимайте ничего наугад. Напишите в чат команды — разберём вместе.
