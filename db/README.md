# db — база данных

Отвечает: Дугарова А.

Единственное место, где описаны таблицы. `collector/` и `api/` берут модели и подключение отсюда и своих таблиц не заводят.

| Файл           | Что в нём                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------ |
| `database.py`  | Подключение к базе по `DATABASE_URL` из `.env` (`engine`, `SessionLocal`, `get_db`)                                |
| `models.py`    | Таблицы SQLAlchemy: `vk_communities`, `vk_posts`, `categories`, `events`, `users`. Поля — по `docs/event_format.md` |
| `init_db.py`   | Создаёт таблицы, заполняет 6 категорий и 15 сообществ из `docs/communities.md`                                     |
| `seed_test.py` | 11 тестовых мероприятий с датами от сегодняшнего дня — только для разработки                                       |

Запуск из корня репозитория:

```bash
python -m db.init_db      # таблицы, категории, сообщества; повторный запуск безопасен
python -m db.seed_test    # тестовые мероприятия, если в базе ещё нет ни одного
python -m pytest tests/test_db.py
```

## Таблицы

| Таблица          | Что хранит                                     | Важное                                                                       |
| ---------------- | ---------------------------------------------- | ---------------------------------------------------------------------------- |
| `vk_communities` | Сообщества-источники                           | `owner_id` уникален и отрицателен; `is_active = false` — не собирать          |
| `vk_posts`       | Исходный текст поста ВК                        | Пара `community_id` + `vk_post_id` уникальна: повторная загрузка не создаёт дубль |
| `categories`     | 6 категорий                                    | `slug` уникален: `sport`, `science`, …                                       |
| `events`         | Мероприятие из поста или из формы              | `source` — `vk`/`form`, `status` — `pending`/`published`/`rejected`, проверяются базой. У заявки из формы `post_id` пустой |
| `users`          | Администраторы (ФТ-12)                         | `username` уникален, пароль — только хеш (НФТ-06)                            |

Пост и мероприятие хранятся отдельно, чтобы сверять разбор с исходным текстом. Дата и время мероприятия — в разных полях: время часто не указано.

## Правила

- Поменяли таблицу — обновите `docs/event_format.md` в том же PR. Миграций нет: после изменения таблиц локальную базу проще удалить (`calendar.db`) и создать заново.
- Локально используется SQLite, при размещении — PostgreSQL: меняется только `DATABASE_URL`. Адрес вида `postgres://…` от Render или Neon подходит как есть; Neon требует `?sslmode=require` в конце.
- В SQLite включена проверка внешних ключей, как в PostgreSQL: ссылку на несуществующую категорию или пост база не примет.
- Список сообществ меняется в двух местах: `docs/communities.md` и `COMMUNITIES` в `init_db.py`. Тест сверяет, что они совпадают.
